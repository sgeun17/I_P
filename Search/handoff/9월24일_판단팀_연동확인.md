## 현재 전달 가능한 것

검색 출력 버전은 `retriever-0.2`입니다. 문서 전체 Top-5, 후보별 요구사항, 관련 청크 ID와 원문을 제공합니다. Python 함수·명령행 JSON 인터페이스가 있으며 HTTP 검색 서버는 없습니다.

판단팀 코드 추가 후 검색팀에 `judgment_adapter.py`를 구현했습니다. 아래 원본 검색 JSON을 직접 넣는 대신 변환한 MappingInput을 전달합니다. [변환 예제](../examples/judgment_mapping_input.json)와 [연결 결과·사용법](판단팀_코드확인_연결결과.md)을 먼저 확인하세요. 아래 JSON은 실제 검색 출력이며 판단 모델을 실행한 결과는 아닙니다. 입력팀의 파일 파서·청커와 검색 모듈을 연결한 검사는 업로드 API·DB를 거치지 않고 로컬 파일로 실행했습니다.

원본 DOCX를 제외한 파일은 검색팀이 만든 합성 시험 자료입니다. 예상 ID는 검색 전에 기록한 초안이며 실제 운영 정확도를 평가하는 독립 정답셋이 아닙니다.

## 읽을 필드

1. `success`: false이면 `error`를 처리하고 후보 배열에 접근하지 않습니다.
2. `retrieval.candidates`: 문서 전체 Top-K. rank, control_id, similarity_score, best_chunk_id 포함.
3. `candidate_controls`: 위 후보와 같은 ID·순서의 요구사항. control_id로 연결합니다.
4. `evidence_chunks`: 증적 원문과 위치. best_chunk_id 및 matched_chunk_ids로 연결합니다.
5. `warnings`: 현재 입력팀 필드 차이를 보정한 기록. 무관 증적 경고나 품질 점수가 아닙니다.

판단팀은 필요하면 청크별 상세 `retrieval.chunk_results`도 참고할 수 있습니다. `matched_chunk_ids`는 해당 후보가 청크별 Top-K에 포함된 목록이며, 인용 검증 통과나 적합성 확정을 뜻하지 않습니다.

검색 점수는 청크별 코사인 유사도의 최댓값입니다. 정답 확률 또는 LLM confidence와 구분해야 합니다. 무관한 문서도 후보 5개가 나오며, 검색팀은 이번 검사 결과만으로 임의의 관련성 임계값을 추가하지 않았습니다.
