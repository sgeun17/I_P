# 9월 25일 Phase 1 검수 및 무관 증적 정책

## 현재 완료 범위

- KB 101개 ID·명칭·필수 필드 재검사 통과. 중복·누락 없음.
- 전체 KB 재색인 및 새 프로세스 재조회 통과. 101개 자기 벡터 검색 일치, 예시 3건 직접 코사인 계산과 일치.
- [검수용 스냅샷](../releases/phase1-review-2026-09-25/README.md)에 KB·원문 기준·모델 revision·캐시 식별자·DB 버전·검사 보고서 보존.
- 검색팀 단위 검사 19개, 최신 판단팀 기존 검사 277개 통과.
- 기존 실측 검색 20건과 새 경계 검색 10건을 분석. 판단팀의 새 어댑터와 검색팀 변환 함수가 30건에서 같은 입력 모델 생성.
- 최신 판단팀 프롬프트 생성까지 확인하고 정상·무관·애매 사례의 호출용 요청 예제 4건을 저장. 실제 LLM 호출은 하지 않음.

검색 기능 구현과 로컬 검증은 준비됐습니다. **KB 사람 검수·독립 정답 승인·실제 LLM 및 업로드/화면 통합 검증까지 끝난 상태는 아닙니다.** 스냅샷은 최종 배포 버전으로 표시하지 않았습니다.

## 관련 없음은 누가 검증하나

| 담당 | 검증 대상 |
|---|---|
| 검색팀 | 관련 증적의 정답 후보가 Top-5에 들어오는지, 무관 증적 점수와 겹치는지, 필터를 두면 관련 증적을 잘못 버리는지 |
| 판단팀 | 실제 LLM이 무관한 증적을 NOT_RELATED/NO_MATCH로 처리하는지, 관련 증적을 NO_MATCH로 잘못 제외하는지, UNCERTAIN과 호출 실패를 구별하는지 |
| 공동 | 같은 검수된 사례로 검색 포함률과 최종 판단 결과를 각각 측정하고, 실제 연결과 정책을 승인 |

Top-K는 “현재 KB에서 상대적으로 가까운 후보 K개”입니다. 무관한 문서에 후보가 반환되는 것과 그 문서를 통제항목에 최종 매핑하는 것은 구분합니다.

## 오늘 점수 실험

[상세 결과](../reports/relevance_2026-09-25/summary.md)는 합성 사례 30건의 검수 전 라벨을 사용합니다. 관련 19건, 무관 7건, 애매 4건입니다. 기존 20건은 조건이 일치하는 저장된 실측값을 재사용하고 새 10건만 오늘 실제 검색했습니다.

- 관련 증적 Top-1 점수 범위: **0.537245~0.786998**.
- 무관 증적 Top-1 점수 범위: **0.336163~0.569209**.
- 애매한 증적 Top-1 점수 범위: **0.529183~0.666794**. 애매 사례는 관련/무관 정답 분모에서 제외.
- `0.55 미만 제외` 가정: 관련 증적 1/19건 잘못 제외, 무관 증적 1/7건 여전히 후보화.
- `0.60 미만 제외` 가정: 무관 증적 7건은 모두 제외되지만 관련 증적 2/19건도 잘못 제외.

짧은 계정 회수 증적보다 “계정·접근권한·로그·암호·백업” 단어가 나오는 낱말 퍼즐의 점수가 높았습니다. 현재 관측으로는 점수만으로 관련 없음이라고 확정하기 어렵습니다. 작은 합성 세트의 관측이며 실제 운영 성능으로 일반화하지 않습니다.

따라서 운영 검색의 후보 삭제나 임계값은 추가하지 않았습니다. 이후 임계값을 도입하려면 독립적으로 검수한 실제 증적 세트에서 무관 통과율과 관련 증적 오제외율을 함께 측정해야 합니다.

## 최신 판단팀 정책 확인

- 프롬프트는 검색됐다는 사실·순위·점수를 관련성 근거로 사용하지 않도록 명시합니다. 실제 사용자 프롬프트에는 검색 점수를 빼고 통제항목 요구사항과 원문을 전달합니다.
- 후보별 NOT_RELATED 및 문서 NO_MATCH를 지원하며, 초기 NO_MATCH는 R204로 사람 검토에 들어갑니다.
- UNCERTAIN은 R107, 검색 고득점과 NO_MATCH의 충돌은 R206, 호출 실패는 FAILED와 별도 사유로 구분합니다.
- 네 분기는 실제 service 코드에 고정 응답을 넣어 확인했습니다. **LLM이 올바르게 무관함을 판단하는지는 아직 검증하지 않았습니다.**
- 9/24의 YAML 미연결 지적은 해결됐습니다. 최신 코드는 Python Thresholds가 원본이고 YAML은 자동 생성된 설명 파일입니다. YAML 직접 수정 요청을 다시 할 필요는 없습니다.

## 판단팀에 전달할 답변

관련 없음 처리 정책은 필요합니다. 검색팀에서 추가 확인한 합성 사례에서는 관련·무관 점수 범위가 겹쳐 단순 점수 기준으로 후보를 없애면 관련 증적도 누락됐습니다. 우선 검색은 Top-5를 유지하고, 현재 판단팀에 구현된 NOT_RELATED/NO_MATCH와 불확실 검토 정책으로 처리하는 방향을 제안합니다. 검색팀은 점수 분포와 후보 포함 여부를 제공하고, 판단팀에서는 같은 사례를 실제 LLM에 넣어 무관 증적의 NO_MATCH 처리와 관련 증적의 오제외 여부를 함께 확인해 주세요.

## 재실행

Search 폴더에서 기존 로컬 환경으로 실행합니다.

```powershell
.\.venv\Scripts\python.exe -B -X utf8 validate_kb.py
.\.venv\Scripts\python.exe -B -X utf8 chroma_index.py
.\.venv\Scripts\python.exe -B -X utf8 tests/evaluate_relevance_policy.py
.\.venv\Scripts\python.exe -B -X utf8 record_phase1_snapshot.py
```

재색인은 실행 중인 검색이 없을 때 수행합니다. 평가의 기존 검색 결과는 KB 해시와 임베딩 캐시 식별자가 일치할 때만 재사용합니다. 달라지면 기존 평가부터 다시 검색해야 합니다. KB가 바뀌면 같은 이름의 스냅샷을 덮어쓰지 않고 새 검수 버전으로 기록합니다.
