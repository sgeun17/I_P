## 이번에 보완한 문서 단위 검색

이전 출력은 청크마다 5개 후보와 후보 합집합을 제공했습니다. 현재는 `retrieval.candidates`에 **문서 전체의 후보 5개**가 순서대로 나옵니다. 같은 통제항목의 청크별 유사도 중 최댓값으로 문서 순위를 정하고 중복을 제거합니다.

- `retrieval.candidates`: 판단팀이 먼저 읽을 문서 Top-K.
- `retrieval.chunk_results`: 청크별 검색 상세. 문서 Top-K와 별도.
- `best_chunk_id`: 해당 문서 점수에 가장 크게 기여한 청크.
- `candidate_controls`: 문서 후보와 같은 순서의 K개 요구사항.
- `evidence_chunks`: 인용할 원문과 위치 정보.

검색팀 범위는 **통제항목 KB → 벡터 색인 → 후보 검색 → 판단팀 입력 제공**입니다. 특정 통제항목에 최종 매핑할지, 증적이 요건을 충족하는지, 인용이 적절한지, confidence와 검토 큐를 어떻게 처리할지는 판단팀의 기능입니다.

## 실행한 검증

- 단위 검사 14개 통과: 입력 검증, 호환 처리, 문서 집계·중복 제거·동점·음수 점수, DB 오류·KB 불일치, 기존 임베딩 캐시 동작 등.
- 실제 DOCX 청크 검색 통과: 다른 작업 폴더에서 Python 호출, 명령행 결과 일치, 문서 Top-5 및 JSON Schema 검사.
- 합성 샘플 20건 실행: 예상 정답이 있는 15건 모두 예상 ID가 문서 Top-5에 포함. 단일 정답 Top-1은 11/12.
- S10 재해복구 훈련 샘플은 예상 2.12.2가 3위이며 2.11.4가 1위. 훈련·복구 표현이 유사한 기준끼리 순위가 섞이는 사례를 그대로 기록했습니다. 1위만 최종 정답으로 처리하면 안 됩니다.
- 무관 문서 3건도 각 5개 후보 반환. 관련성 임계값은 없으며 점수는 정답 확률이 아닙니다. 애매한 문서 2건은 확정 정답을 부여하지 않고 품질 지표에서 제외했습니다.

위 수치는 KB 요구사항을 참고해 만든 **개발용 합성 샘플과 자동 작성 정답 초안**에서 얻은 결과입니다. 실제 운영 정확도 또는 최종 품질 승인으로 표현하지 않습니다. 검색 결과를 본 뒤 정답을 바꿔 맞추지 않았습니다.
