# 9/27 LLM 연결 전 검증과 연결 준비

## 확인한 결과

- 실제 파일 11건: 정상 9건이 최신 파일 dispatcher·청커·BGE-M3·ChromaDB·MappingInput·프롬프트 생성까지 통과했고 빈 파일·손상 파일 2건은 검색 전에 차단됐다. 모두 합성 시험 파일이다.
- 정상 파일은 TXT(UTF-8/CP949/긴 문서/무관 문서), CSV, DOCX, XLSX, PPTX, PDF다. 페이지/시트/슬라이드와 원문·ID·버전의 보존을 확인했다. PDF는 한 청크가 1~2쪽에 걸치므로 보고서의 시작 페이지 목록은 `[1]`이다.
- PNG·JPG는 **합성 OCR 블록 2건**으로 청킹 이후 연결을 확인했다. 확인한 두 Python 환경에 EasyOCR가 없어 실제 이미지 인식이나 OCR 모델 다운로드는 하지 않았다.
- 고정 응답 10종으로 단일/복수 매핑, 무관, 낮은 confidence, 불확실, 허위 인용, 잘못된 JSON, 호출 실패, PNG/JPG OCR 검토 전환을 확인했다. 실제 LLM 호출 수는 0이다.
- 두 팀의 검색→판단 입력 변환이 같은 모델을 만드는지 대조했고, 프롬프트에서 검색 점수·순위가 제외되는지 확인했다.
- 회귀 검사: 검색팀 24개(새 이미지/OCR 경계 검사 5개 포함), 판단팀 277개 통과. 스키마·정책 검사 49개 통과. 이전 파일 검사 도구의 최신 DOCX/TXT 파서 및 문자열 ID 연결도 2건 확인했다.

[실행 보고서](../reports/pre_llm_2026-09-27/summary.md), [상세 기록·코드 해시](../reports/pre_llm_2026-09-27/summary.json), [TXT 호출 전 프롬프트](../reports/pre_llm_2026-09-27/TXT_prompt.json).

고정 응답은 검증 코드의 동작을 확인하기 위해 후보 선택과 confidence를 지정한 시험값이다. 모델 정답·검색 정확도·LLM 성능으로 집계하지 않는다. 업로드 API, 운영 MySQL, 화면은 이번 실행 경로에 포함되지 않는다.

## 재현한 문제와 수정

1. 입력팀은 PNG/JPG를 지원하지만 검색 허용 형식·출력 스키마·판단 FileType이 6종에 머물러 있었다. PNG/JPG를 추가하고 Pydantic 모델에서 판단 입력 스키마를 재생성했다. 이미지 페이지 값은 null을 유지한다.
2. 청커가 OCR 블록을 `source=parser`로 내보냈다. 겹침 처리 후 실제 기여 블록을 기준으로 출처를 결정하고 이미지 입력은 OCR로 보존한다. 고정 응답에서 OCR 검토 사유 R207과 REVIEW_REQUIRED 전환을 확인했다.
3. 기존 파일 검사 도구는 폐기된 `docx-test`, `chunk` 경로와 정수 증적 ID를 사용했다. 최신 dispatcher·`chunking`·문자열 ID로 변경했다. 새 실행 결과는 실행일 폴더에 저장해 9/24 기록을 덮어쓰지 않는다.
4. 이미지 인용 안내를 포함한 프롬프트 버전은 `phase1_mapping_v0.4`다. 서버의 이미지 멀티모달 호출을 추가한 것은 아니며 텍스트 OCR 청크를 전달한다.

입력 형식·스키마·출처 동작 수정은 로컬 변경이며 팀 규격 최종 승인을 대신하지 않는다.

## 사용자 참고안과 미정 값

| 구분 | 9/27 전달받은 방향 | 아직 필요한 확정 |
|---|---|---|
| 서빙 | Ollama 우선, vLLM 차순위 | 실제 실행 서버·설치 위치 |
| 인터페이스 | OpenAI-compatible API, 기존 규격 사용 | 실제 endpoint·method·요청/응답 규격 파일 위치 |
| 모델 | Qwen3 시리즈, 사양에 따라 결정 | 정확한 모델 ID·모델 크기·양자화·컨텍스트 및 메모리 요구 |
| Structured Output | Pydantic JSON Schema | 서버가 받는 Schema 전달 형식 및 실제 강제 여부 |
| 접속 | localhost | 실제 포트·경로·인증 필요 여부 |
| 생성·운영 | 미정 | 출력 토큰 한도, Qwen3 출력/추론 설정, timeout·재시도 연결 |

이 표는 참고안이며 실행 설정이 아니다. 현재 터미널에서 Ollama 명령과 기본 포트 11434의 리스너는 확인되지 않았다. 다른 포트나 별도 환경의 실행 여부까지 확인한 것은 아니다.

기존 저장소에는 MappingInput·출력 Schema·프롬프트·검증/재시도 정책이 있지만 실행용 HTTP 클라이언트와 LLM endpoint 계약은 찾지 못했다. 저장된 `*_prompt.json`은 messages와 output_schema를 담은 서버 독립 요청 재료이며 곧바로 보낼 확정 HTTP body가 아니다.

서버가 준비되면 정확한 모델·접속 규격을 확인하고 실제 응답을 기존 `build_result`에 연결한다. 먼저 정상·복수·무관·불확실 사례의 실제 인용과 판단을 확인한 후 호출 실패·재시도와 업로드/저장/화면을 검증한다.
