# 9/27 입력·검색·판단팀 변경내역

## 변경 상태

LLM 연결 전 검증에서 재현한 연동 문제를 수정한 로컬 변경이다. 이 작업에서 커밋·푸시·팀 메시지 발송은 하지 않았다. 팀 규격 최종 승인을 받은 변경은 아니다.

## 입력팀: 코드 1개, 문서 1개

| 파일 | 변경 전 | 변경 후 | 이유 |
|---|---|---|---|
| `phase1_입력/chunking/chunker.py` | OCR로 읽은 블록도 최종 청크에서 `source=parser`로 표시됨 | 겹침 처리 후 기여 블록 중 OCR이 있으면 `source=ocr`; PNG/JPG도 OCR로 유지 | 판단팀의 OCR 검토 신호가 소실되는 문제 해결 |
| `phase1_입력/chunking/README.md` | 수정 설명 없음 | 출처 보존 동작과 검증 결과 링크 추가 | 변경 이력 공유 |

청크 본문, 크기·겹침 설정, 파서 및 OCR 인식기, 업로드 API, DB 처리 코드는 이 작업에서 수정하지 않았다. OCR 출처 변경은 사람 검토 대상 여부에 영향을 준다.

## 판단팀: 코드 2개, 생성 스키마 1개, 문서 2개

| 파일 | 변경 내용 | 영향 |
|---|---|---|
| `phase1_판단/src/enums.py` | `FileType.PNG`, `FileType.JPG` 추가 | 입력팀이 이미 내보내는 이미지 청크를 판단 입력에서 허용 |
| `phase1_판단/src/prompts.py` | PNG/JPG 인용 페이지는 null이라는 안내 추가; 프롬프트 버전 v0.3→v0.4 | 이미지 OCR 텍스트의 인용 위치 규칙 명시 |
| `phase1_판단/schemas/phase1_mapping_input.schema.json` | Pydantic 모델에서 재생성하여 PNG/JPG 반영 | 입력 스키마와 코드 일치 |
| `phase1_판단/docs/output_schema_v0.3.md` | 지원 형식 설명 갱신 | 입력 규격 문서 일치 |
| `phase1_판단/docs/llm_harness_status_v0.1.md` | 연결 전 검증 결과와 미확정 Ollama/Qwen3 참고안 기록 | 실제 LLM 미연결 상태 명시 |

판정·인용 검증·검토 정책·confidence 임계값·결과 집계 로직은 이 작업에서 수정하지 않았다. 기존 정책이 보존된 OCR 출처를 받아 사람 검토로 전환하도록 연결한 것이다. PNG/JPG 허용은 입력 Enum 확장이므로 판단팀에 변경 공유가 필요하다.

## 검색팀 변경

- `chunk_retriever.py`, `schemas/chunk_output.schema.json`: PNG/JPG 입력·출력 허용.
- `tests/verify_file_pipeline.py`: 이전 폴더 경로·정수 증적 ID를 최신 dispatcher·문자열 ID에 맞춤. 실행일별 결과 폴더 사용.
- `tests/test_image_pipeline_contract.py`: OCR 출처·이미지 형식·페이지 규칙 회귀 검사 5개 추가.
- `tests/verify_pre_llm_pipeline.py`: 실제 파일→검색→판단 입력·프롬프트와 고정 응답 검증 도구 추가.
- `reports/pre_llm_2026-09-27/`, 인계·진행현황 문서: 결과와 실행 방법 기록.

이전 원문 검토에서 수정한 기준 초안은 WBS 작업 구분에 따라 현재 `I_P/phase2_기준/`에서 관리하며, 과거 원문 대조 결과는 `reports/source_review_2026-09-27/`에 보존한다. 검색 KB `controls.json`과 검색 순위·집계·임계값은 두 작업 모두 변경하지 않았다.

## 확인한 검사

- 검색팀 단위 검사 24개, 판단팀 277개 통과.
- 판단팀 스키마·정책 검사 49개 통과.
- 실제 합성 파일 정상 9건, 빈 파일·손상 파일 차단 2건, 합성 OCR 블록 2건 연결 검사.
- 고정 응답 10종 검증·검토 전환 확인. 실제 LLM 호출과 실제 이미지 OCR은 미실행.

## 검색팀 Phase 1 잔여 작업

| 구분 | 남은 작업 | 지금 진행 가능 여부 |
|---|---|---|
| KB 내용 | 나머지 98개 통제항목의 요구사항·증거 예시와 원문 대조 | 가능. 전체 101개 구조 검사는 이미 완료했지만 내용 검수와는 다름 |
| 평가 정답 | 기존 검색 사례의 예상 정답을 검색 순위와 독립적으로 검토; 애매·복수 항목 근거 기록 | 초안 검토 가능. 사람이 최종 확정해야 독립 정답으로 사용 가능 |
| 검색 품질 | 검토한 정답으로 Top-K 포함률과 실패 사례 평가·개선 | 정답 검토 뒤 가능. 합성 자료 결과와 운영 성능은 구분 |
| 버전 고정 | 내용·정답 검수 결과를 반영한 KB/색인/설정/평가 기록 고정 | 검수 뒤 가능. 현재는 검수용 스냅샷 |
| 협업 | 입출력 형식·점수 의미·오류 처리 규격 승인 | 자료 준비 가능, 최종 팀 합의 필요 |
| 통합 | 실제 LLM 및 업로드·DB·화면 연결 검증 | 해당 실행 환경 준비 필요 |

따라서 검색 기능의 구현·로컬 연결 검증은 진행됐지만, LLM을 기다리지 않고 할 수 있는 검색팀 Phase 1 작업도 남아 있다.
