## 후보 인용 검증 수정

`mapped_controls[].citations`가 정상이어도 `candidate_decisions[].citations`에 없는 청크·다른 증적/버전·허위 인용·잘못된 page가 있으면 검증 실패로 남기고 기존 정책대로 사람 검토로 보낸다. `NOT_RELATED`/`UNCERTAIN`의 인용을 새로 필수화하지는 않으며, 제공된 인용만 검사한다.

두 목록의 같은 통제항목·청크·페이지·정규화된 인용은 중복 검사하지 않는다. 페이지 값이 다르면 각각 검사한다. 기존 `E407` 정책은 유지했다. 페이지형 청크에 `page=null`이면 비차단 경고, 실제 범위를 벗어난 page는 `E404` 오류다.

## 검색→판단 연결 사용

검색팀 폴더와 기존 `.venv`에서 사용한다. 실행 모델명은 환경에 맞게 명시하고 기존 판단팀의 LLM 설정을 재사용한다. 아래 호출은 실제 서버가 준비된 뒤 실행한다.

```python
from judgment_adapter import read
from judgment_pipeline import JudgmentRequestError, run_judgment
from llm_config import get_model_name_from_env

search_result = read("reports/chunk_search_result.json")
try:
    outcome = run_judgment(search_result, model=get_model_name_from_env())
except JudgmentRequestError as error:
    print("LLM 요청 오류:", error.status_code)
else:
    result = outcome.mapping_result
    status = outcome.evidence_status
    retries = outcome.llm_run.retry_count
```

함수는 원본 검색 결과를 변경하거나 파일을 자동 저장하지 않는다. `mapping_result`에 증적 ID/버전, KB 해시, 프롬프트·규칙·모델 버전, 검증·검토 결과와 처리 시간이 있다. 호출 원문은 기존 runner의 `llm_run`에 보존한다.

HTTP 4xx는 아직 합의된 공통 오류코드가 없으므로 `JudgmentRequestError`로 중단하고 상태를 보존한다. 빈 JSON이나 정상 `NO_MATCH`로 조립하지 않는다. 5xx·JSON 파싱 오류의 재시도와 실패 상태는 기존 판단팀 정책을 따른다. 토큰 예산 검사도 기존 설정·토큰 카운터를 전달한다. 최종 모델의 실제 토크나이저 검증은 별도다.

## Phase1→Phase2 검수 조회

`phase2_기준`을 모듈 경로에 넣고 기존 검색팀 Python 환경에서 호출한다.

```python
from checklist_store import ChecklistStore
from phase1_review_adapter import prepare_review_plan

plan = prepare_review_plan(
    result,
    ChecklistStore(),
    "phase2-checklist-draft-2026-09-28",
    allow_draft=True,
)
```

`ChecklistStore()`는 이미 적재된 검수용 DB를 읽는다. 적재·조회 방법은 [Phase2 README](../../phase2_기준/README.md)에 있다. 선택한 버전의 저장된 파일 해시·KB 출처 메타데이터를 대조하며, 조회할 때 원본 PDF를 다시 해시하는 기능은 아니다.

처리 완료와 기존 사람 검토 게이트가 필요하다. 자동 확정 결과는 저장된 검증 플래그 5개와 오류 목록도 검사한다. 사람이 `APPROVED`/`MODIFIED`로 확정한 결과는 기존 판단팀의 결정 권한을 유지한다. 원래 검증 오류가 남았으면 `phase1_validation_overridden_by_review=true`로 표시하며, `phase1_validation_scope=STORED_RESULT_ONLY`로 저장된 검증 결과임을 밝힌다. 사람이 고친 인용을 새로 검증했다고 주장하지 않는다.

현재 질문이 있는 항목은 `2.5.1`, `2.5.6`, `2.9.3`이다. 1:N 매핑 중 하나라도 범위에 없으면 `CHECKLIST_SCOPE_MISSING`과 누락 ID로 전체 계획을 보류한다. 확정된 `NO_MATCH`는 질문 0개다. 계획은 `review_only=true`, `approved=false`이며 문항 판정·종합 등급·운영 Phase2 API 규격을 만들지 않는다.

[연결 검사 JSON](../reports/team_integration_2026-09-30/summary.json)에는 단일 매핑 20문항, 1:N 매핑 34문항, 범위 누락 전체 보류, 확정 NO_MATCH 0문항, 후보 허위 인용 `E403`/`R104`, HTTP 404 명시 중단을 기록했다. 상태 전이를 위한 승인도 합성 시험 값이며 실제 사람 승인이나 정답 라벨이 아니다. 검사 중 KB·질문·사유 코드·저장 검색 출력 12개 파일의 해시가 유지됐다.
