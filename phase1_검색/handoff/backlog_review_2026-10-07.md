현재 `phase2_판단/tools/run_validated_phase2.py`는 전체 체크리스트·사유 코드 기본값과 `critical_policy={"mode":"explicit"}`를 이미 사용한다. 이전의 “critical CLI 연결이 필요하다”는 요청은 현재 코드에서 해소됐다. `phase2_통합`의 결과·검토 이력 모듈도 존재한다. 다만 이것만으로 실제 웹·DB·보고서 전체 연결이 완료된 것은 아니다.

## 서버 확인과 통합 시험의 남은 조건

사용자가 지정한 서버를 읽기 전용으로 확인했다. Ollama와 Qwen3:14B는 사용 가능했다. 8765 포트 프로세스는 `http.server`이며 통합 앱으로 확인되지 않았다. 확인한 서비스·포트·사용자 홈의 제한된 탐색 범위에서는 실행 중인 통합 DB/앱이나 연결 설정을 찾지 못했다. 다른 위치나 다른 서버에 없다는 뜻은 아니다. 확인 후 SSH 터널을 종료했다.

전체 시험에는 실제 통합 앱 실행 위치, 테스트 DB 연결 설정, 시험용 사용자/권한, 보고서 생성 경로가 필요하다. 다른 팀 코드는 수정하지 않았다.

## 권한·감사·보존 적용 시 전달할 초안 (미확정·미적용)

- 권한: 원본 조회, 다운로드, 검토 결과 변경을 각각 허용할 역할을 정하고, 비로그인·권한 없는 사용자 요청을 거부하는 시험을 포함한다.
- 감사: 행위자, 행위 종류, 증적 ID/버전, 실행 시각, 성공/실패, 추적 ID를 기록한다. 원문·비밀번호·토큰을 감사 로그에 복제하지 않는다. DB 저장 실패 처리도 시험해야 한다.
- 보존: 원본/모델 요청·응답/감사 로그 각각의 보존 기간, 기산일, 삭제 권한, 보존 예외를 합의한 후 적용한다. 기간이 없는 상태에서 임의 삭제를 실행하지 않는다.

10/8 오류 처리와 10/9 Top-K·청크 조정은 후속 일정이다. Top-K 웹 옵션은 사용자가 보류했으므로 이번 작업에서 구현하지 않았다.
