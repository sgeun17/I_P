## 10/9 실행

- 실제 BGE 18개 합성 사례 × 4개 청크 조건 = 72회 비교. 기존 청크 유지가 이 세트에서 유리. Top-5·청킹·임계값은 변경하지 않음.
- Top-3/5/7/10 실제 호출의 반복 시간·어댑터 변환·입력 JSON 크기를 별도로 측정. LLM 호출은 없으므로 LLM 속도 향상 수치로 인용하지 않음. 결과는 reports/topk_calls_2026-10-09.json.
- 오류/계약 42개 테스트, 청크/해시/어댑터/재사용 33개 테스트 통과: 합계 75개, 세부 사례 24개. 고정 응답·모의 transport 검사가 포함되어 실제 서버 장애 시험과 구분.
- 실제 EasyOCR 모델 누락 초기화 실패에서 FAILED 상태 전환과 이전 청크 삭제 호출 확인. DB 대체 호출 사용, 실제 인식·DB 저장은 미검증.
- 개발용 4개 데이터 묶음과 E0004 평가 후보를 정리. 중복 가능하며 승인 정답셋으로 승격하지 않음.

## 다음 순서

10/9 후속 업데이트: 아래 3~4번의 로컬 시험은 추가 수행했다. 상세한 완료 범위와 잔여 사항은 ../../phase2_통합/handoff/system_integration_2026-10-09.md 및 ../../phase2_통합/reports/system_integration_2026-10-09.json을 우선 참고한다. 공동 서버 배포와 로컬 시연은 구분한다.

1. 원문과 기준으로 평가 대상의 required/related/excluded 항목을 독립 검토한다. E0004의 1.1.6도 제안 상태이므로 확정 전에는 정답 분모로 쓰지 않는다.
2. 10/10 예정 평가(Top-1/3/5 포함률·최종 매핑 정확도·체크리스트 정답 비교)를 확정 라벨 범위에서 실행한다. 개발용 100%를 운영 정확도로 발표하지 않는다.
3. 통합 담당과 시험 DB·웹 실행 위치를 확인하고 업로드→Phase1→Phase2→검토→보고서 한 건을 실행한다. 기준팀 새 실행기 연결도 여기서 확인한다.
4. OCR 실패 원인 분리, 공식 검토 신호 매핑, 접근 권한·감사·보존 문제를 담당 팀에 전달하고 반영 후 재검증한다. 기존 타 팀 코드는 변경하지 않았다.
5. 검증 범위와 잔여 결함을 표시한 뒤 배포본·태그를 고정한다. 커밋·푸시·태그 생성은 이번에 수행하지 않았다.
