# 10/9 안정화 작업

WBS Y47 Top-K·청킹·임계값 조정, X47 오류 처리, X49 평가 증적 후보 수집에 해당한다. 검색팀 폴더에만 도구·결과를 추가했고 운영 기본값과 다른 팀 기존 코드는 변경하지 않았다.

## 검색 비교

실제 로컬 BGE와 현재 색인으로 기존 합성 스트레스 18건 × 청크 4조건 = 72회 검색했다. 전체 101개 후보 순위의 prefix로 Top-1/3/5/7/10을 비교했다. 기대 통제항목은 총 24개이며 사람이 승인한 독립 정답이 아니다.

| 청크 조건 | Top-3 포함 | Top-5 포함 | Top-7 포함 | Top-10 포함 |
| --- | --- | --- | --- | --- |
| 기존 합성 청크 | 24/24 | 24/24 | 24/24 | 24/24 |
| 합친 뒤 400자 | 19/24 | 20/24 | 21/24 | 22/24 |
| 합친 뒤 800자 | 17/24 | 18/24 | 20/24 | 20/24 |
| 합친 뒤 1600자 | 17/24 | 18/24 | 20/24 | 20/24 |

글자 수 조건은 overlap 없는 진단용 분할이지 입력팀 실제 청킹 구현이 아니다. 기존 합성 자료가 짧고 관련 근거가 청크로 잘 분리되어 있다는 한계가 있다. 이 수치를 운영 정확도 또는 최적 청크 크기로 사용하지 않는다. 기록한 시간은 전체 K 검색 시간이며 모델 최초 로드 포함 여부를 표시했다. K별 LLM 지연시간을 측정한 것이 아니다.

결정: 현재 Top-5와 운영 청킹/집계 유지. 미승인 라벨의 합성 18건만으로 후보 수를 줄이거나 임계값을 새로 넣지 않는다. 기존 E0004의 1.1.6 후보 순위 문제는 별도이며 이번 실행에서 실제 증적을 재평가하지 않았다. 웹 Top-K 옵션은 이번 범위에 포함하지 않았다.

근거: `reports/topk_chunks_2026-10-09.json`, 재실행 도구 `tools/benchmark_topk_chunks.py`.

## 오류 처리

- 검색→판단·이미지 계약 17개 + 세부 사례 2개 통과.
- 판단팀 LLM 클라이언트/재시도 기존 테스트 25개 통과. 타임아웃·연결 실패·HTTP 오류는 모의 HTTP transport 시험이며 실제 서버 장애를 발생시킨 것은 아니다.
- 실제 EasyOCR를 다운로드 금지·빈 모델 디렉터리로 초기화해 FileNotFoundError 재현. 입력 파이프라인에서 PREPROCESSING → FAILED/FILE_PARSE_FAILED 전환과 이전 청크 삭제 호출 확인. DB는 대체 호출이므로 저장 트랜잭션까지 확인한 것은 아니다. OCR 인식은 실행하지 않았다.
- 읽기 전용 코드 검토: 스캔 PDF OCR 예외는 parser_dispatcher._ocr_scanned_pdf에서 기존 empty_document로 반환하여 모델 누락/런타임 오류가 빈 문서와 구별되지 않을 수 있다. 입력팀에 예외 원인 분리 요청 필요. 이미지 파이프라인 전체가 무조건 멈추는 문제로 보고하지 않는다.

근거: `reports/ocr_missing_model_2026-10-09.json`, 재실행 도구 `tools/probe_ocr_failure.py`.

## 평가 준비

개발용 4개 묶음(20/18/10/24건)과 실제 E0004 로컬 자료의 존재·라벨 상태·원본 해시를 정리했다. 파생/중복 사례가 있어 합계를 독립 증적 수로 사용하지 않는다. E0004의 1.1.6은 검토 제안이지 정답 확정이 아니다.

`reports/evaluation_readiness_2026-10-09.json`에 정답 확정에 필요한 필드를 기록했다. 실제 원문을 읽고 required/related/excluded 통제항목과 인용 근거를 사람이 확인한 뒤 10/10 평가 지표·설정 동결을 진행해야 한다. 평가 입력 누락을 임의 라벨 승인으로 채우지 않았다.

남은 통합 작업: 실제 DB를 포함한 업로드→보고서 E2E, 실제 OCR 인식/스캔 PDF 실패 분류, 실환경 LLM 장애, 승인 정답셋 기반 최종 지표 및 배포본 동결. 이 문서의 시험 통과만으로 해당 항목을 완료 처리하지 않는다.
