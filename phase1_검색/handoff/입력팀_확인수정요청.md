# 입력팀 확인·수정 요청

작성일: 2026-09-23 / 대상: 현재 `I_P/입력` 코드. 아래는 검색 연결을 위해 확인한 내용입니다. **입력팀 원본 코드는 수정하지 않았습니다.**

## 먼저 맞춰야 하는 네 가지

| 항목 | 현재 확인된 동작 | 요청하는 결과 |
|---|---|---|
| 모듈 경로 | `chunker.py:1`의 `from chunk_links ...`가 일반 import에서 ModuleNotFoundError. 파일은 하위 chunk 폴더에 있음 | 팀 공통 실행 진입점에서 경로 임시 설정 없이 청킹 모듈을 불러올 수 있게 정리 |
| 파일명·추출 방식 | make_chunks에 source_file이 없음. 글 청크의 source는 파일 경로, 표 청크의 source는 parser | 공통 정의대로 `source_file=원래 파일명`, `source=parser/ocr`를 모든 청크에 동일하게 적용 |
| 증적 ID | 저장 모듈은 문자열 `"000001"`, 청킹 ID 함수는 양의 정수만 허용. 문자열을 그대로 전달하면 ValueError | 증적 ID의 자료형·표현을 저장→청킹→검색에서 통일. 검색팀 제안은 저장값과 같은 문자열을 보존하는 것 |
| 공통 형식 검증 | `finalize_chunks`, `validate_chunks`가 있지만 make_chunks에서 사용하지 않음. 실제 DOCX 3개 청크 모두 source_file 누락으로 검사 실패 | 최종 청크가 공통 규격 검사를 통과하도록 조립·검증하고 실제 출력 예제 제공 |

참조 위치: `chunker.py:1,33,97`, `chunk/chunk_format.py:44,58,73,94`, `database/evidence_store.py:83`.

## 텍스트의 의미를 바꿀 수 있는 문제

**페이지를 넘긴 표의 머리글 보완 함수가 호출되지 않습니다.** `chunk/table_chunker.py:108`의 `fill_continued_headers`는 구현돼 있지만 현재 make_chunks에서 호출하지 않습니다.

2페이지 합성 표로 재현한 결과:

```text
원래 머리글: 계정 | 승인자 | 상태
다음 페이지 행: user002 | 담당B | 삭제
               user003 | 담당C | 활성

현재 청킹: user002: user003 | 담당B: 담당C | 삭제: 활성
기존 머리글 보완 함수를 먼저 적용하면:
계정: user002 | 승인자: 담당B | 상태: 삭제
계정: user003 | 승인자: 담당C | 상태: 활성
```

요청: 청킹 전 이어진 표 보완을 연결하고 실제 PDF 표로 확인해 주세요. 검색팀에서는 잘못 변환된 본문을 추정해서 고치지 않습니다.

## 규칙 확인이 필요한 부분

- **겹침**: 100글자 overlap은 한 개의 긴 블록을 분할할 때만 적용됩니다. 짧은 문단 여러 개를 모으다 크기 한도로 나누는 경계에는 적용되지 않습니다. 의도된 정책인지 확인이 필요합니다.
- **800 기준**: 현재 800은 토큰이 아니라 글자 수입니다. 검색팀은 별도로 실제 모델 토큰 길이를 검사하고 초과 시 오류를 반환합니다.
- **원본 파일명**: DOCX 파서는 전달 경로 전체를 source_file로 반환하고, 다른 파서는 파일명만 반환합니다. 저장명이 `000001_v1.docx`라면 원래 파일명은 저장 메타데이터의 file_name에서 전달해야 합니다.
- **페이지 의미**: PDF=페이지, PPTX=슬라이드, XLSX=시트, DOCX/TXT/CSV=null. 판단팀 인용에서도 같은 의미로 사용할 예정입니다.
- **파서 오류**: errors가 있으면 make_chunks는 []만 반환합니다. 상위 호출부에서 오류 내용을 잃지 않도록 전달이 필요합니다.
- **부분 추출 실패**: PDF 일부 페이지, XLSX 일부 시트, PPTX 일부 슬라이드의 추출 실패를 건너뛰면서 errors가 비어 있을 수 있습니다. 누락을 알리는 warnings/상태 제공 여부를 검토해 주세요.
- **업로드 연결**: main.py의 /analysis/start는 queued 응답과 TODO만 있고 실제 파서/청커 호출은 없습니다. 파일→파서 선택→청킹 실행·결과 전달을 어느 진입점에서 수행할지 확인이 필요합니다.
- **OCR**: 이 디렉토리에서 이미지 OCR 실행 연결은 확인되지 않았습니다. source=ocr가 실제로 나오는 시점과 입력 형식 확인이 필요합니다.

## 검색팀에서 임시로 처리한 범위

검색팀의 `--compat-input`을 명시적으로 켜면 현재 출력의 정수 ID를 6자리 문자열로 바꾸고, **호출자가 제공한 원래 파일명**으로 누락된 source_file을 보충하며, 기존 source의 파일 경로를 parser로 바꿉니다. 모든 변환은 출력 warnings에 기록됩니다. 청크 ID·본문·위치 정보는 변경하지 않습니다.

기본 모드는 위 형식 차이를 오류로 반환합니다. 임시 호환은 입력팀 수정이나 팀 간 규격 확정을 대신하지 않습니다. 표 머리글 오류·누락된 본문은 호환 모드에서도 고치지 않습니다.
