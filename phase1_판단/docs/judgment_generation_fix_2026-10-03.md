# Phase 1 판단 생성 오류 보완 기록 — 2026-10-03

## 1. 근거 실행

RTX 5080, `qwen3:14b` 환경에서 시험증적 33건을 실행했다.

- 파싱/OCR: 33/33 성공
- BGE-M3 검색: 33/33 성공
- 총 청크: 147개, OCR 청크: 5개
- 판단 완료: 11건, 실패: 22건
- Validator 통과: 10건
- LLM 호출은 전부 1회 성공했으며 전송 재시도는 없었다.

오류 발생 횟수는 `E501` 22, `E202` 22, `E504` 21, `E403` 15,
`E505` 9, `E404` 2였다. 한 문서에 같은 코드가 여러 번 있을 수 있으므로 오류 횟수는
문서 수와 같지 않다.

## 2. 원인

Validator는 규칙대로 오류를 탐지했다. 실패의 중심 원인은 다음 생성·실행 계약이었다.

1. 생성용 JSON Schema에서 `mapped_controls`가 필수가 아니어서 모델이 생략할 수 있었다.
2. 런타임은 `candidate_decisions`에 RELATED가 있으면 `MATCHED`를 파생하지만,
   생략된 `mapped_controls`는 빈 배열로 읽혀 `E504`와 `E501`이 발생했다.
3. Pydantic 형식 파싱 뒤의 의미·인용 검증은 최종 조립 단계에서만 실행되어,
   `E403`·`E404`·`E501`·`E504`를 교정 재시도할 기회가 없었다.
4. 일부 모델 응답은 인용문의 띄어쓰기를 바꾸거나 청크 범위 밖 페이지를 출력했다.

`rows.json`의 실패 행에 보인 `NO_MATCH`는 모델의 실제 NO_MATCH 판단이 아니라,
잘못된 MATCHED 응답을 안전한 실패 객체로 만든 fallback 값이다.

## 3. 변경

- 프롬프트 버전을 `phase1_mapping_v0.7`로 올렸다.
- 생성 Schema에서 `mapped_controls`를 필수로 강제했다. 최종 저장 Pydantic 모델의
  하위 호환 기본값은 건드리지 않았다.
- 출력 전 RELATED 수, PRIMARY 1개, 인용 원문, 페이지 범위를 점검하도록 명시했다.
- 형식 파싱 직후 전체 Validator를 실행하고, 아래 네 코드만 교정 지시와 함께 1회 재시도한다.
  - `E403`: 인용문 원문 불일치
  - `E404`: 인용 페이지 범위 불일치
  - `E501`: PRIMARY 개수 오류
  - `E504`: MATCHED인데 매핑 없음
- `E505`는 재시도하지 않고 기존대로 Human Review 신호로 유지한다.
- 실제 모델 응답과 런타임 정규화 응답을 재실행 산출물에서 분리 저장한다.

## 4. 검증과 남은 확인

자동 테스트는 구조 누락, PRIMARY 누락, 변형 인용, 페이지 오류,
`E505` 혼합 및 재시도 소진 사례를 포함한다. 로컬 전체 판단 테스트를 통과해야 한다.

실제 효과 수치는 같은 서버에서 저장된 33개 `search.json`으로 판단만 재실행한 뒤 확정한다.
목표는 기존 22건의 구조 실패 감소이며, 모델의 의미상 매핑 정확도와 Human Review 비율은
별도 평가 대상이다. 이 변경은 Validator를 느슨하게 하거나 오류 결과를 자동 승인하지 않는다.
