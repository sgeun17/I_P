# 기준팀 공통 실행 규칙 v1 (2026-10-07)

사용자의 독립 진행 요청에 따라 정한 운영 기본값이다. 법정 기간·조직 정책을 새로 정한 것이 아니다. 문항별 evidence_rule의 구체적 인정 조건을 우선하며 원문에 없는 사실을 만들지 않는다.

## 최신성·기준일·평가 기간

- 실행 시 전달한 assessment의 as_of와 period_start/period_end를 사용한다. 현재 날짜나 파일 수정 시간을 평가 날짜로 추정하지 않는다.
- 실제 이행 문항은 해당 대상·사건·평가 기간의 이행인지 확인한다. 작성일만으로 수행일을 대신하지 않는다. 기간 연결이 불명확하면 UNKNOWN, P2_U_TIME_OR_VERSION_UNCLEAR로 검토한다.
- 기준·절차 존재 문항은 평가 시점에 유효하게 적용되는 버전인지 확인한다. 오래된 작성일만으로 무효라고 하지 않고, 최근 작성일만으로 유효하다고 하지 않는다.
- 모든 문서에 최근 12개월 같은 일률적 만료를 만들지 않는다. 문항/확인된 조직 정책의 주기·기한이 있으면 그것을 적용한다. 지정된 월 단위 최신성 정책은 별도 날짜 검사도 수행한다.
- 보존 기간, 정기 수행 주기, 문서 최신성은 서로 다른 조건이다. 하나의 수치를 다른 조건으로 바꾸지 않는다.

## 인정 증적

- 확장자와 증적의 의미는 다르다. 확장자가 PDF라고 적합한 것도, TXT라고 부적합한 것도 아니다. 별도 allowed_types가 없으면 내용 기준으로 검토한다.
- procedure는 기준·방법·책임·절차 내용, record는 해당 사건의 실제 이행 기록, implementation은 실제 설정·운영 상태를 문항 기준에 맞춰 확인한다.
- 백업 절차서는 실제 백업 수행의 증거가 아니다. 문항이 요구하지 않는 별도 문서 제목·승인 형식을 추가로 요구하지 않는다.

## critical

- 체크리스트에 확정된 critical 불리언과 explicit 종합 정책을 사용한다. 중요도는 증적을 MET으로 인정하거나 NOT_MET을 UNKNOWN으로 바꿀 이유가 아니다.

## 적용 범위·예외

- 동일 대상·기간의 사건 미발생이 직접 확인되고 별도 문항 예외가 없으면 UNKNOWN + P2_U_NO_TRIGGER_EVENT로 사람 검토에 남긴다. 미제출을 미발생으로 추정하지 않는다.
- 적용되는 기한이 아직 오지 않았다면 UNKNOWN + P2_U_NOT_YET_DUE로 사람 검토에 남긴다. N/A나 MET을 자동 생성하지 않는다.
- 3.3.2-Q02의 미발생+사전 통지 방침 예외 및 2.10.8-Q05의 관리표·작성 지침 인정 조건은 해당 evidence_rule대로 유지한다. 사건 미발생 예외 하나를 다른 문항으로 확장하지 않는다.

## 상충 근거

- 대상·사건·기간이 다른 자료는 곧바로 상충으로 처리하지 않는다.
- 동일 범위에서 상충하고 어느 근거가 유효한지 직접 확인할 수 없으면 UNKNOWN + P2_U_EVIDENCE_CONFLICT로 사람 검토에 남긴다. 상충하는 양쪽의 근거를 설명한다.
- 단지 최신 작성일, 문서 제목, 문서 개수 또는 낮은 확신도를 이유로 임의의 한쪽을 선택하거나 잠정 MET으로 통과시키지 않는다.
- 정정·폐기·대체 관계와 적용 시점이 원문에 직접 확인되면 유효 근거를 선택한 이유와 인용을 남긴다.

UNKNOWN은 자료 미확정에 대한 보수적 실행 기본값이다. 별도 사람 검토 UI/DB 구현 완료를 뜻하지 않는다. 날짜·내용의 의미 판정은 LLM 및 검토 대상이며 이 규칙을 전달한 사실만으로 정확성을 보증하지 않는다.
