# 공통 정책 연결 방법

기준팀의 `tools/run_with_criteria_policy.py`를 추가했다. 판단팀 기존 파일을 수정하지 않으므로 **기존 명령이나 웹에서 자동 사용되지는 않는다.** 이 실행기를 사용하거나 `prepare`/`execute`를 호출해 연결해야 한다.

## 실행 예 (날짜는 예시, 실제 평가 범위로 변경)

`phase2_기준` 폴더에서 준비 상태만 확인한다. 네트워크 호출과 파일 출력은 없다.

```powershell
python tools/run_with_criteria_policy.py --control-id 2.5.1 --as-of 2026-10-07 --period-start 2026-01-01 --period-end 2026-06-30 --prepare-only
```

실제 실행은 위 명령에서 `--prepare-only`를 빼고 `--input <Phase2 입력 JSON> --model qwen3:14b --out-dir <새 결과 폴더>`를 추가한다. LLM 접속은 기존 판단팀 환경 설정을 그대로 사용한다. 출력 폴더가 이미 있으면 덮어쓰지 않는다. `--policies <문항별 정책 JSON>`은 기존 판단팀 CLI와 같은 형식이다.

```json
{
  "2.5.1-Q01": {
    "freshness": {"max_age_months": 6, "date_label": "performed_date"},
    "allowed_types": ["txt", "pdf"]
  }
}
```

위 6개월·확장자 목록은 **입력 형식 설명용이지 채택한 기준이 아니다.** 필요하지 않은 정책 키는 생략한다. 정책이 없는 문항은 문항 내용과 평가 기간으로 의미 검토하며, 기존 날짜·확장자 감사 결과의 `POLICY_MISSING`은 숨기지 않는다. 해당 표시를 FRESH/ALLOWED로 고쳐 승인처럼 보이게 하지 않는다.

## 적용 범위

- 기간 역전·미래 평가 종료·잘못된 날짜·미등록 문항 ID·오타 정책·불명확 날짜 역할·잘못된 확장자 목록은 LLM 실행 전 차단한다.
- 기준일은 결정적 월 단위 검사에, 평가 기간과 공통 규칙은 기존 `organization_context`에 전달한다. 시스템 규칙·문항 기준이 우선한다. 기존 기본 판정 규칙을 교체하지 않는다.
- 기간 내 이행·절차 유효성·상충 근거·사건 발생 여부는 의미 검토이며 정규식으로 사실을 확정하지 않는다. v2 실행기는 Self-check 전송 어댑터에도 동일 평가 기간과 공통 기준을 전달한다. 증적 원문·재시도 메시지는 변경하지 않는다.
- explicit critical을 사용한다. 원본 체크리스트·사유 코드·기대값은 변경하지 않는다.
- `audit.criteria_execution_policy`에 정책 범위·규칙 해시·평가 기간을 남긴다. 미발생/미도래/상충 UNKNOWN은 `pending_item_reviews`에도 기록한다. v2는 한 문항이라도 이 목록에 있으면 `human_review.required=true`, `REVIEW_REQUIRED`로 연결한다. 공식 전용 코드가 없어 기존 P2R113 미등록 신호 처리와 provisional 표시를 사용하며 다른 검토 사유는 보존한다. **DB 큐에 직접 저장하지는 않는다.**

## 판단·인터페이스팀에 필요한 후속 수정

1. 날짜/확장자 검사를 켜면 `FRESHNESS_DATE_MISSING`, `FORMAT_MISMATCH` 등이 `SELF_CHECK_SIGNALS` 미등록 경고를 낸다. 현재 결과는 P2R113/provisional 및 검토 필요로 보존된다. 날짜 검사의 가능한 상태들을 함께 등록·검증해야 한다.
2. `CRITERIA_PENDING_ITEM_REVIEW`의 공식 전용 사유 매핑은 인터페이스팀에서 정해야 한다. 현재는 누락하지 않고 P2R113/provisional로 검토 상태에 연결한다. DB/웹은 이 실행 결과를 소비해야 한다.
3. 기존 판단팀 CLI를 계속 쓸 경우 v2와 동등한 Self-check 프로필 전달을 적용해야 한다. 새 기준팀 실행기를 쓰면 별도 판단팀 수정 없이 전달된다.

고정 응답 연결 테스트와 실제 Qwen3:14B 합성 시험은 구분한다. 실제 모델 회귀 시험은 `tools/verify_runtime_policy_llm.py --base-url <로컬 Ollama v1 주소> --out-dir <새 폴더>`로 실행한다. 시험의 6개월/PDF 정책은 합성 조건일 뿐 운영 기본값이 아니다. 실제 증적 정확도·웹/DB 검토 큐 연결 완료를 뜻하지 않는다.

2026-10-07 v2 실제 시험: 이행 기록, 사건 미발생, 해소되지 않은 상충, 기한 미도래, 명시 정책상 기간 초과, 명시 정책상 형식 불일치, 절차만 존재하는 7개 합성 사례 모두 기대 결과와 일치했다. 최종 출력 JSON Schema도 7건 모두 통과했다. 근거는 `reports/runtime_policy_llm_2026-10-07.json`에 있다. 단일 문항을 선택한 시험이며 전체 883문항 실증적 정확도 검증이 아니다.

## 표의 여섯 정책에 대한 v2 결론

| 항목 | 기준팀 실행 기본값 / 구현 | 검증 범위 |
| --- | --- | --- |
| 최신성 | 모든 증적에 일률적 만료를 두지 않는다. 문항 내용·유효 버전·평가 기간으로 검토하고 명시된 월 정책이 있을 때 결정적 검사도 수행한다. | 기간 초과 합성 사례 UNKNOWN 확인. 조직별 실제 정책 값은 입력 대상이다. |
| 기준일·기간 | 실행 시 필수 입력, 기간 역전 차단, Grounding/Self-check에 동일 전달 | 입력 경계 및 실제 이행/미도래 사례 확인 |
| 인정 증적 | 확장자보다 내용, 절차와 실제 이행 구분. 별도 명시된 형식 제한만 검사 | 절차만 있는 기록 문항 및 명시 형식 불일치 UNKNOWN 확인 |
| critical | 기존 explicit 값 유지 | 이전 341개 지정·집계 검증 유지 |
| 적용·예외 | 사건 없음/미도래 UNKNOWN, 기존 문항별 예외 우선, 검토 필요 상태 연결 | 실제 모델 미발생/미도래 UNKNOWN 및 검토 필요 확인 |
| 상충 | 동일 범위 미해결 상충 UNKNOWN, 작성일만으로 우선하지 않음, 검토 상태 연결 | 실제 모델 상충 사례 UNKNOWN 및 검토 필요 확인 |

이 기본값은 법정·조직별 의무 기간을 대신하지 않는다. 실제 평가 대상·기간과 특별 정책을 입력하는 것은 실행 데이터 준비에 해당한다. 웹에서 이 진입점을 호출하도록 연결하고 실제 조직 증적으로 검증하는 작업은 별도다.
