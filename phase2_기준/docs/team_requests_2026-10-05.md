## 검색팀 후속 재현 방법

원문 청크가 포함된 검색 입력 JSON을 받으면 검색 폴더에서 다음 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -X utf8 tools/diagnose_aggregation.py --input <검색_입력.json> --expected 1.1.6 --output reports/e0004_aggregation.json
```

현재 모델·색인의 전체 후보를 조회해 max/mean/top3 mean/RRF를 비교한다. 보고서에는 원문 청크를 복사하지 않고 점수·순위·입력 해시를 기록한다. 1.1.6은 평가 기준으로만 사용하며 런타임 후보에 강제 삽입하지 않는다. 기존 다중 청크 개발 사례도 `--dataset tests/review_cases.json`으로 비교할 수 있다. 이번에는 E0004 실측이나 다문서 모델 재평가를 수행하지 않았다. 합성 점수의 진단 단위 테스트만 실행했다.

## 판단·인터페이스팀 전달 사항

1. `full_checklist_draft.json` / `full_reason_codes_draft.json` 두 파일을 r4 쌍으로 동기화한다. 기준 검수 모듈과 Schema도 함께 반영한다.
2. Phase2 입력의 checklist_version을 r4로 다시 연결한다. 기존 r1 결과 파일·audit는 수정하지 않는다.
3. `run_control_judgment(..., critical_policy={"mode":"explicit"})`로 호출해야 한다. 현재 CLI는 이 인자를 노출하지 않아 기본 check_kind 정책을 사용한다. 판단팀에서 명시적 정책 선택을 연결해야 한다.
4. critical은 통제 분야로 결정하므로 기록(record) 문항을 일괄 비중요 처리하면 안 된다. 2.5·2.6·2.10·2.11 밖의 절차·이행 문항은 false이다.
5. 최신성 정책은 문항별 `freshness.max_age_months`, `freshness.date_label`과 실행 `as_of`가 필요하다. 문서 최신성이 단순 경과 개월 수로 표현 가능한지부터 합의한다. 유효한 정책 문서는 작성일이 오래됐다는 이유만으로 무효로 간주하지 않는다.
6. 현재 `allowed_types`는 PDF/DOCX 등 **파일 확장자** 검사다. 기준팀의 정책서·승인 이력·로그 등 **증적의 내용 종류** 인정 여부를 대신하지 않는다. 두 개념을 합의 없이 동일시하지 않는다.

### 추가 발견: 판단팀의 종합 판정 모듈 경로 불일치

pull 이후 인터페이스 모듈은 `phase2_인터페이스/overall_result.py`에 있으나, 판단팀 `validation/contracts.py`의 `interface_module("overall")`은 이전 `phase2_인터페이스/test/overall_result.py`를 참조한다. 이전 위치에는 파일이 없어 해당 로딩 경로에서 FileNotFoundError가 발생한다. 판단팀에서 현재 경로로 수정해야 한다. 이번 작업에서는 다른 팀 코드를 수정하지 않았다. 기준팀의 저장·조회 테스트 통과가 이 판단팀 실행 경로의 정상 동작을 뜻하지 않는다.

## 아직 필요한 결정

- 문항별 최신성 검사가 필요한지, 기준 날짜의 의미(작성일·수행일·시행일 등), 인정 기간과 근거.
- 실행 기준일. 현재 날짜를 조용히 고정하지 않는다.
- 문항별 제한할 파일 형식이 있는지와 내용상 인정 증적의 조건.
- 사건 미발생·기한 미도래·예외 처리. 기존 UNKNOWN 보류를 유지한다.

다른 팀의 OCR, 인용 생성, Self-check, 공식 검토 사유 코드는 이번 수정 범위 밖이다.
