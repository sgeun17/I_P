# Phase2 사유 코드 검수 초안 — 2026-09-29

WBS O25의 사유 코드 고정을 준비하는 자료다. **13개 사유 코드 제안·사례 연결·구조 검증까지 준비하며, 팀의 의미 합의와 최종 코드 고정은 남아 있다.** 상태는 `DRAFT_FOR_TEAM_REVIEW`, `approved=false`다.

현재 대상은 기존 3개 통제항목·54개 질문이다. 체크리스트의 원문·질문·ID·근거 조건과 기존 162개 합성 사례·기대 판정은 바꾸지 않는다. 사례별 코드와 근거 발췌를 별도 파일에 연결했다. 실제 조직의 판정 결과나 LLM 성능 검증 자료가 아니다.

## 사유 구분

`NOT_MET`는 당시 적용되는 문항 기준에 대한 **직접적인 미수립·미수행·불일치 확인**이 있을 때의 초안이다. 필요한 자료가 제출되지 않았다는 사실은 `UNKNOWN` 사유다. 모든 코드는 질문의 자연어 기준과 검토 대상·사건·기간에 종속된다.

| 코드 | 의미 | 대표 검토 사례 |
|---|---|---|
| `P2_NM_RULE_NOT_DEFINED` | 필수 절차·규정·기준 등이 미수립 상태라고 직접 확인 | EX-017: 해지 절차 미수립 확인 |
| `P2_NM_REQUIRED_ACTION_NOT_DONE` | 당시 필요한 실행·기록·검토·개선 행동을 하지 않았다고 직접 확인 | EX-068: 실제 계정 등록 후 이력을 남기지 않음 |
| `P2_NM_RULE_VIOLATED` | 실제 상태·처리가 당시 적용 기준과 다름을 직접 확인 | EX-02: 업무에 불필요한 권한, EX-134: 적용 보관기간 전 삭제 |
| `P2_U_EVIDENCE_INSUFFICIENT` | 자료 미제공 또는 일부 내용 누락 | EX-015: 등록 신청만 있고 실제 처리 자료 없음 |
| `P2_U_SCOPE_OR_RULE_UNCLEAR` | 자료의 적용 범위 또는 판정 기준을 확인할 수 없음 | EX-018: 다른 시스템 절차의 적용 관계 불명 |
| `P2_U_SUBJECT_OR_EVENT_UNLINKED` | 같은 대상·사건·백업본 등을 설명하는 자료인지 연결되지 않음 | EX-021: 이름만 있고 계정·종료 요청 연결 없음 |
| `P2_U_TIME_OR_VERSION_UNCLEAR` | 수행일·검토기간·당시 효력·적용 버전을 확인할 수 없음 | EX-06: 검토 기간과 수행일 불명 |
| `P2_U_EVIDENCE_UNREADABLE` | 필요한 본문·값이 흐림·손상·가림 등으로 판독 불가 | EX-030: 권한변경 절차 이미지 본문이 흐림 |
| `P2_U_EVIDENCE_CONFLICT` | 동일 대상·사건·시점의 근거가 상충하고 유효 근거를 정할 수 없음 | EX-054: 동일 건·버전의 승인과 반려가 상충 |
| `P2_U_NO_TRIGGER_EVENT` | 조건부 이행을 검토할 사건이 없다고 확인되었고 적용 제외 처리가 미합의 | EX-060: 검토 기간 전보·퇴직 사건 없음 |
| `P2_U_EXCEPTION_UNRESOLVED` | 공유계정 등 예외 적용·승인·책임추적성 검토 미완료 | EX-066: 공유계정 예외 판단에 필요한 정보 없음 |
| `P2_U_NOT_YET_DUE` | 적용 기한이 기준일 이후이고 중간 상태 처리 정책 미합의 | BC-01: 후속조치 기한 전, 아직 진행 중 |
| `P2_U_OBSERVATION_INCOMPLETE` | 의무 기간은 확인됐으나 필요한 관찰기간·대상 전체를 확인할 자료가 부족 | BC-02: 최근 백업 한 건으로 과거 대상의 기간 이행 확인 불가 |

각 코드의 사용 조건·오용 방지 조건·필요한 정보는 [reason_codes_draft.json](reason_codes_draft.json)에 있다. 예시의 기간·기한은 합성 조직 가정이며 인증기준의 고정 수치가 아니다.

## 경계를 검토할 때 지킬 점

- 문서가 오래됐다는 사실만으로 최신성 부족을 판정하지 않는다. 검토 시점의 효력·기간·적용 버전이 확인되지 않으면 `TIME_OR_VERSION_UNCLEAR`, 필요한 관찰 구간 전체가 확인되지 않으면 `OBSERVATION_INCOMPLETE`를 검토한다.
- 자료가 없는 것과 사건이 없다고 직접 확인한 것을 구분한다. 사건 없음·기한 미도래·예외 검토 미완료는 현재 초안에서 `UNKNOWN`과 협의 ID로 표시한다. 자동 충족·미충족·적용 제외 승인을 부여하지 않는다.
- 후속조치 문항은 검토 기준일에 이행해야 하는 단계의 이행을 확인한다. 기한 전의 모든 단계까지 완료해야 한다는 기준을 추가하지 않는다. BC-01의 UNKNOWN은 진행 중인 사건의 최종 결과 표현이 미합의라는 경계 제안이며, 현재 도래한 단계의 미이행을 뜻하지 않는다.
- 다른 대상·시점의 자료를 곧바로 상충으로 보지 않는다. 작성일이 최신이라는 이유만으로 유효 자료를 정하지 않는다.
- 복구시험의 완전성·정확성·절차 적절성 **확인을 수행했는가**와 시험 결과가 좋았는가는 다른 질문이다. 해당 확인을 수행한 직접 근거가 있으면 결과 불량만으로 그 확인 문항을 `NOT_MET`으로 바꾸지 않는다.
- 미수행과 기준 불일치는 사유 설명의 구분이다. 한 사례가 여러 사유를 뒷받침하면 여러 코드를 연결할 수 있으며, 배열 순서는 우선순위를 뜻하지 않는다.
- `MET`의 미충족·판단불가 사유 코드는 빈 배열이다. 충족 설명과 실제 인용은 별도의 판단 출력 계약에서 정한다.

## 준비한 연결과 검증

[reason_code_examples.json](reason_code_examples.json)은 기존 162개 사례 ID·문항·기대 판정을 그대로 참조하고, 실제 사례 텍스트에서 발췌한 근거·사유 설명·협의 ID를 더한다. 기존 사례에 없던 기한 미도래와 관찰기간 부족은 별도 `BC-01`·`BC-02` 합성 경계 사례로 구분한다.

[reason_codes.py](reason_codes.py)는 사유 목록 조회와 연결 구조 검증만 수행한다. 텍스트에서 판정을 추측하거나 실제 증적을 판정하지 않는다. `allow_draft=True`를 명시해야 사용할 수 있다.

```powershell
python reason_codes.py list --result UNKNOWN --allow-draft
python reason_codes.py validate --allow-draft --report reports/reason_code_validation_2026-09-29.json
python -m unittest discover -s tests -p test_reason_codes.py -v
```

검증은 원본 파일 해시·버전, 전체 문항/사례 연결, 결과와 코드의 호환, 중복·미등록 코드, 원문 발췌, 협의 ID, 모든 코드의 사례 확보를 확인한다. 사유 선택의 의미는 AI 보조 검토이며 사람의 정답 승인과 실제 증적·LLM 실행 검증을 대체하지 않는다.

팀이 정의와 경계를 승인하면 승인 버전·코드 호환 정책을 정하고 판단·인터페이스에 연결한다. 현재 O25의 **초안 준비는 완료**, **팀 합의 및 최종 고정은 미완료**로 기록한다.
