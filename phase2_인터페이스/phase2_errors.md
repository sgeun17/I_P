## 3. 검토로 보내지 않고 기록만 하는 것 — 7개

`P2E001` `P2E002` `P2E006` `E407` `P2E503` `P2E506` `P2E901`

**틀린 결과가 아니기 때문이다.**

- `P2E001`·`P2E002` — 판정 대상이나 질문지가 없는 건 정상 결과(`증적 없음`)다
- `P2E006` — 미승인 체크리스트는 **지금 전건에 해당**해서 검토 신호가 못 된다
- `P2E506` — **판단팀이 `E506`(`REASON_TOO_SHORT`)을 검토로 안 보내는 것과 맞췄다.**
  근거가 부실한 것이지 틀린 게 아니다. 프롬프트 개선 자료로만 쓴다.
  임계값도 판단팀 `validators.REASON_MIN_CHARS = 10` 과 같은 값을 쓴다.
- `P2E901` — 배치 중단은 결과 하나의 문제가 아니라 운영 사건이다

## 4. ★ 핵심 규칙 — 문항 하나의 실패가 통제항목을 망가뜨리지 않는다

판단팀이 Phase 1 에서 세운 원칙을 그대로 따른다.

> 이 상태에서는 판단을 시도하지 않는다. 그래도 **결과 객체는 반드시 만든다.**
> 증적 하나가 판단 불가라고 배치가 멈추거나 화면에서 사라지면 안 된다.
> — `phase1_판단/src/enums.py`

Phase 2 는 문항마다 LLM 을 부른다. 한 질문지가 647문항인데 한 문항이 터졌다고
전부 날리면 다시 돌리는 비용이 너무 크다.

**문항 하나가 끝내 실패하면:**

```python
{ "item_id": "2.5.1-Q11",
  "result": "UNKNOWN",          # ← NOT_MET 이 아니다
  "reason": "판정하지 못했습니다 (LLM_TIMEOUT): ...",
  "citations": [],              # UNKNOWN 은 비워도 되는 유일한 값
  "error_code": "E101" }
```

`NOT_MET` 으로 두면 **요건을 안 지켰다고 확인한 것**이 된다. 확인을 못 한 것과 다르다.

통제항목은 나머지 문항으로 계속 가고, 검토 사유만 붙는다.

### 통제항목 전체가 `FAILED` 인 경우는 둘뿐

| 상황 | 결말 |
|---|---|
| 입력이 규격 위반 (`P2E005`) | `FAILED` |
| 배치 중단 (`P2E901`) | `FAILED` |
| 판정 대상·질문지 없음 (`P2E001`·`P2E002`) | `COMPLETED` — '증적 없음' |
| 문항 일부 실패 | `COMPLETED` 또는 `REVIEW_REQUIRED` |

## 5. 재시도

**판단팀 `DEFAULT_RETRY_POLICY` 를 그대로 쓴다.** 새 정책을 만들지 않는다.

```
max_retries     1
timeout         60초
backoff         2.0초
retry_on        LLM_TIMEOUT, LLM_CONNECTION_FAILED, LLM_SERVER_ERROR,
                LLM_EMPTY_RESPONSE, LLM_TRUNCATED_RESPONSE,
                JSON_PARSE_FAILED, SCHEMA_INVALID
```

### 배치 중단 — 지금은 구현하지 않는다 (결정 2026-10-02)

Phase 1 은 증적 하나에 LLM 을 **한 번** 부른다. Phase 2 는 **문항마다** 부른다.

| | |
|---|---|
| 정상일 때 | 647문항 × 34초 = **6.1시간** |
| LLM 이 죽었을 때, 중단 없음 | 647 × 2회 × 60초 = **21.6시간을 버림** |
| 배치 중단 켜면 | 연속 5건에서 멈춤 = **10분** |

**그래도 넣지 않기로 했다.**

- 문항마다 결과가 찍히므로 전부 실패하면 **5분 안에 눈에 띈다.** 21.6시간은
  아무도 안 보고 있을 때만 나오는 숫자다
- 멈추고 싶으면 `Ctrl+C` 로 된다. 이미 되는 걸 코드로 또 만드는 셈이다
- **시간만 버릴 뿐 데이터가 깨지지 않는다.** 실패한 문항은 `UNKNOWN` 으로 남는다
- 7명이 손으로 돌리는 도구다. 아무도 안 보는 채로 밤새 도는 상황이 없다

상수는 `phase2_errors.py` 에 남겨뒀다. 아무도 호출하지 않으면 아무 일도 일어나지 않는다.
나중에 실제로 당하거나 무인 실행이 생기면 그때 쓴다.

```python
BATCH_ABORT_AFTER = 5
BATCH_ABORT_ON = ("E101", "E102", "E103")   # 서버가 죽은 신호일 때만
```

## 7. 검증

`test/run_error_check.py` 가 저장소와 대조해 검사한다.

```
① 판단팀 코드와 번호 충돌            [O] 안 겹침 (P2E 19개 / P2R 14개)
② 재사용 선언 17개가 실제로 있는가     [O] 전부 있음, 이름도 같음
③ phase2_판단 하네스와 맞는가        [O] RetryPolicy·ErrorCode 재사용 확인
④ 모든 오류가 분류됐는가             [O] 36개 = 검토 29 + 기록만 7
⑤ 실패 상황 12가지의 검토 판정        12/12
⑥ 통제항목 결말 → 상태              7가지
⑦ 재시도 비용                      6.1시간 / 21.6시간 / 10분
```

⑤ 에 넣은 상황:

```
[O] 정상 — 전부 충족                검토=False
[O] LLM 을 끝내 못 불렀다            P2R106, P2R107
[O] 재시도까지 했는데 JSON 깨짐        P2R101, P2R107
[O] MET 인데 근거 없음              P2R105
[O] 인용이 청크 원문과 다름            P2R104
[O] 질문지에 없는 문항을 지어냄          P2R103
[O] critical 문항 미충족           P2R201
[O] 절반 이상 UNKNOWN             P2R202
[O] 전부 UNKNOWN                P2R204
[O] OCR 청크를 인용                P2R203
[O] 근거가 너무 짧음                 검토=False  ← 기록만
[O] 질문지가 없어 판정 안 함            P2R107
```

## 8. 정해진 것 / 남은 것

| | 내용 | |
|---|---|---|
| `P2R` 코드 14개 | 이걸로 간다 | 확정 (판단팀 확인 요청) |
| `P2R203` (OCR) | **켜 둔다.** OCR 증적은 전부 사람이 확인 | 확정 (회의 결정) |
| 임계값 (UNKNOWN 0.5, 근거 10자) | 돌려보고 조정. 합의 안건 아님 | 확정 |
| 배치 중단 | 구현하지 않음. 상수만 남겨둠 | 확정 |

남은 것은 없다. `P2R` 코드만 판단팀이 보고 추가·수정할 수 있는데,
**추가는 기존 값을 건드리지 않는다.** 뺄 때는 번호를 빈자리로 남긴다
(판단팀이 `R204` 를 지우지 않고 조건만 끈 것과 같은 방식).

판단팀 `human_review_policy_v0.1.md` 에 **"Phase 2 Review와 모듈을 공유하는가"** 가
아직 미정으로 남아 있다. 이 규격은 **코드는 나누고 모양은 맞추는** 쪽으로 썼다.
`decide_review()` 가 판단팀 `review_policy.decide()` 와 같은 모양을 돌려준다.
