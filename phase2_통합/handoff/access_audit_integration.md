# 접근통제·감사로그 연결 (2026-10-09)

WBS S46 원본 접근 역할·권한 적용 / T46 조회·다운로드·검토 이력 기록의 **독립 모듈 구현**.
후속 작업으로 tools/run_system_demo.py의 별도 로컬 API에 연결하고 실제 HTTP·DB 검증을 수행했다. 상세는 system_integration_2026-10-09.md 참고. 공동 웹 전체에 적용 완료한 상태는 아니며 기존 다른 팀 파일은 수정하지 않았다.

## 추가 모듈

`phase2_통합/access_audit.py`의 `AccessAudit(database, grants)`를 사용한다.
grants는 역할별 허용 작업의 명시적 매핑이다. 기본 허용 역할은 없다.
작업은 VIEW_ORIGINAL / DOWNLOAD_ORIGINAL / REVIEW다. 실제 역할별 권한표는 배포 설정으로 전달한다.

호출 순서:
1. 웹 서버가 로그인/토큰을 검증해 actor와 role을 얻는다. 요청 본문·헤더의 자칭 역할을 그대로 넣지 않는다.
2. 서버가 조회한 증적 ID와 버전을 고정한다. 조직별 접근 범위가 있으면 별도 검사한다.
3. `guard.execute(actor=..., role=..., action=..., evidence_id=..., version=..., operation=...)` 안에서 실제 작업을 수행한다.
4. AccessDenied는 403, 감사 저장 장애는 503 등으로 처리하고 원본을 반환하지 않는다.

SQLite 감사 저장소는 웹에서 직접 내려받을 수 없는 서버 경로에 둔다.
actor·role·증적 ID/버전·UTC 시각·작업·요청 식별자·결과만 저장한다.
문서 본문, 인증 토큰, 예외 메시지는 저장하지 않는다.
DENIED / STARTED / SUCCEEDED / FAILED를 기록하며 실행 전 감사 저장 실패는 작업을 차단한다.

## 연결 시 주의

- 로그인 구현이나 전역 API 보호 기능이 아니다. 원본 접근의 모든 경로가 이 검사를 거쳐야 한다.
- operation은 동기적으로 완료되는 작업이어야 한다. FileResponse나 generator를 반환하면 실제 읽기/전송을 감싸지 못한다.
- SUCCEEDED는 서버 작업 완료이며 다운로드 수신 완료를 뜻하지 않는다.
- 검토의 상세 변경 전후 값은 기존 phase2_review_store가 계속 기록한다. 이 모듈은 접근 이벤트용이다.
- 기존 DB와 감사 SQLite 사이에는 공동 트랜잭션이 없다. 작업 후 감사 쓰기 실패는 수행된 변경을 되돌리지 못한다. STARTED만 남은 건은 조사 대상이다. 운영 검토 변경과 감사의 원자적 저장은 통합팀 DB 트랜잭션에 연결해야 한다.
- 관리자에 대한 변조 방지/외부 로그 보관, 보존 기간, 자동 정리 작업은 구현하지 않았다. 임의 기간으로 원본이나 로그를 삭제하지 않는다.

## 검증 및 남은 작업

실제 임시 파일 읽기·SQLite 영속 저장, 비인가 접근, 다운로드 권한 분리, 처리 실패, 감사 저장 장애 차단 검증.
검색 worker 회귀 검사 포함 18 tests / 4 subtests 통과. HTTP 로그인·원본 다운로드·검토 DB 연결 시험은 미수행.

남은 연결: 통합 웹의 인증 진입점, 역할별 권한 설정, 원본 API 전체에 guard 적용, 검토 저장 트랜잭션과 감사 연결.
WBS S46/T46 전체 완료 표시는 아직 하지 않는다. U46 보존 규칙과 W46 실제 비인가 웹 접근 검증도 남아 있다.
