# 후보의 범위 추정 및 문서 내용 평가 보완

이 변경은 로컬 개발 후보에 적용했다. 서버와 Git에는 아직 반영하지 않았다.

- 로그 시스템 번호를 시스템 종류에 매핑하는 하드코딩을 제거했다.
- 문서에 등장한 시스템 목록으로 평가 범위를 자동 확대하거나 MET를 UNKNOWN으로 변경하던 규칙을 제거했다.
- 복구시험 주기 정규식 불일치를 근거로 MET를 강제 변경하고 기간·기준일 부재까지 설명하던 규칙을 제거했다.
- UNKNOWN에 복구·보관 관찰 기록이 있으면 원문 인용을 보존하고 원래 사유는 감사 기록에 남긴다. 이 처리는 근거 연결을 확정하지 않으며 SELF_CHECK_UNCERTAIN 검토 신호를 남긴다. 기술·정책 오류와 상충 사유는 덮지 않는다. 추가 인용도 검증한다.
- 판정 프롬프트와 Self-check에 문서 이름 대신 내용을 평가하는 원칙과 문항별 예외 우선순위를 추가했다. 기존 의미 규칙은 유지한다.
- 회사 프로필 입력 기능의 병합은 이 변경에 포함하지 않는다.

검증: 로컬 전체 코드 시험 313 passed, 기존 경고 3건. 합성 실행기에 관리대장 기준/단일 수행/표지만 존재/백업과 복구시험 주기 구분 사례 4건을 추가했다. 실제 Ollama 호출은 실행하지 않았다. 기존 21건과 합쳐 25건이며 기존 21/21 결과를 이 변경본의 결과로 취급하지 않는다.

관찰 기록 추가는 일반적인 의미 오류 해결기가 아니다. 대체 표현을 찾지 못하거나 서로 다른 대상의 기록을 발견할 수 있으므로 결과에 검토 필요를 명시한다. MET의 의미 정확성은 원문 대조 및 모델 회귀시험으로 확인해야 한다.
