# 통합 후보 설명 경계 v2

v1 호환성 30/30, 기술 오류 0건 이후 상세 검토에서 승인시점 허구, Self-check의 기준→이행 확대, 미발생 설명의 후속 기록 부족 언급을 확인했다.

중요 정정: 현재 2.5.1-Q17 evidence_rule.met에는 '승인 주체·시점·결과'가 실제로 있다. 모델이 이를 관찰 사실처럼 reason에 복사했다. 시점 요구가 전혀 없다는 이전 설명은 부정확하다. 기준의 변경 여부는 기준팀에 확인하며 실행 기준/기대값을 임의로 바꾸지 않는다.

수정 범위: grounding과 Self-check 지침, 지침 계약 테스트. 기준은 관찰 사실이 아님을 명시하고 각 주장과 원문의 연결을 검사하도록 보완한다. Self-check 자신의 설명에도 실제 이행을 추가하지 않도록 한다. 조건 미발생은 후속 증적 부족과 분리한다.

판정 후처리·스키마·정답·기준팀 파일은 변경하지 않았다. 자동으로 오류가 차단된다는 코드 보장은 아니다.
로컬 324 passed, 기존 경고 3개. 실제 Ollama는 미실행. 전 버전 30/30을 이번 결과로 승계하지 않는다.
같은 compatibility 30문항으로 비교하며 ACCESS-ROLE-ALIGNED의 라벨과 별도로 승인 시점 추가 여부를 확인한다. 해당 문항 UNKNOWN은 무조건 회귀로 보지 않는다. 다른 문항과 전체 설명은 별도 검토한다.
Git commit/push 없음.

v3 보완: v2 Self-check는 문구 동일성과 별도 확인을 과도하게 요구하여 직접 기록까지 부정했다. 최초 판단 지침은 유지하고, Self-check가 같은 대상·사건의 의미상 직접 표현을 인정하도록 좁혔다. 기준팀 확인 대기 ACCESS-ROLE-ALIGNED는 전체 일치와 별도로 집계한다.

v4 보완: v3에서 Self-check가 직접 위반과 NOT_MET 조건 충족을 인정하면서 UNSUPPORTED로 결론 내린 자기모순 1건을 확인했다. 이유·부족 조건·verdict의 결론 일관성과, 처리 근거 선언이 실제 필수 동의 완료를 증명하지 않는 경계를 추가했다.

v5 보완: 프롬프트만으로 자기모순이 해소되지 않아 구조적 재시도를 추가했다. NOT_MET의 인용에 직접 미수행·생략·위반 표현이 있는데 Self-check가 UNSUPPORTED를 반환하면 한 번 재검토한다. 자동 SUPPORTED로 덮지 않으며, 재검토에서도 대상 불일치·상충 등이 해소되지 않으면 UNCERTAIN/보류한다.

v6 보완: 실제 v5 시험에서 같은 자기모순 응답이 재시도 후에도 반복되어 E202 기술 오류가 새로 발생했다. 따라서 재시도와 E202 전환은 제거했다. 대신 Self-check가 인용과 자기 설명에서 동일한 직접 미이행을 스스로 인정하고, 대상·사건·기간·범위 불일치나 상충 근거를 제시하지 않으면서 단지 NOT_MET 결론의 근거가 부족하다고 한 경우에만 그 Self-check 결론을 자기모순으로 무효화한다. 인용의 부정 표현만으로 적용하지 않으며, 적용 시 원 응답과 guard 사유를 audit에 보존한다. 실제 Ollama 결과는 아직 확인하지 않았고 Git 반영 대상도 아니다.

v7 보완: v6 실제 시험에서 자기모순 guard는 작동했지만 원 Self-check 신뢰도 0.6이 후단 임계값 0.7에 걸려 최종 결과가 다시 UNKNOWN으로 바뀌었다. 원 신뢰도를 조작하지 않고 그대로 감사 기록에 보존하되, 해당 guard가 성립한 경우에만 후단의 low-confidence 전환을 적용하지 않도록 연결한다. 일반 SUPPORTED 저신뢰 결과에는 기존 임계값을 그대로 적용한다.

v8 보완: v7 실제 16문항 상세 검토에서 세 경계를 보완했다. 종이 잠금과 전자 등록만으로 전체 접근 제한을 MET으로 확대한 경우를 UNKNOWN으로 전환한다. 복구시험 실제 기록은 보존하되 적용 시험 주기·대상 기간·기준일이 없으면 그 부족 범위를 정확히 설명한다. 재발 문항은 인용된 재발 사실과 후속대책만 설명하도록 정규화하여 보고연도 등 원문 밖 사실을 만들지 않는다. 문서·E번호별 정답 덮어쓰기는 사용하지 않는다.

v8.1 보완: 전자 사본의 저장 설명과 접근권한 제한 문구 사이가 긴 정상 사례를 30자 탐지 범위가 잘못 차단했다. 동일 인용 안에서 최대 120자 범위의 조회·접근 제한 표현을 인정하도록 수정하고, 단순 등록 사례와 접근 제한 명시 사례를 함께 회귀 테스트한다.
