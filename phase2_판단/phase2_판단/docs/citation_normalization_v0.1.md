# 인용 정규화·허용 경계 v0.1

2026-10-02. 구현: validation/citations.py, normalize().

현재 허용은 Python str.split()이 인식하는 연속 공백을 ASCII 공백 하나로 합치고 양끝 공백을 제거하는 것뿐이다. 파서와 OCR 모두 같은 경계를 적용한다.

| 비교 | 처리 |
|---|---|
| 줄바꿈/탭/NBSP/연속 공백 ↔ 공백 하나 | 허용 |
| `접근 권한` ↔ `접근권한` | 불허; 단어 사이 공백 제거 안 함 |
| `2026` ↔ `2926`, `0` ↔ `O` | 불허; OCR 글자 보정 안 함 |
| 마침표·괄호·쉼표 삭제/교체 | 불허 |
| 대소문자·유니코드 유사 문자·전각 숫자 교체 | 불허 |
| 요약·의역·어순 변경 | 불허 |
| 다른 청크를 합쳐 만든 인용 | 불허 |
| 정상화한 quote가 단일 청크 text의 부분 문자열 | 허용; 의미상 충분성은 Self-check 별도 |

page는 정수이되 bool은 허용하지 않는다. 페이지형 청크에서는 범위 안이어야 한다. null은 E407 경고다. 비페이지형 청크에 임의의 page를 붙이면 E404다.
페이지 범위가 1~2인 청크만으로 특정 문장이 1쪽인지 2쪽인지 확정할 수 없다. 구현은 범위 일치까지만 보장한다.
OCR 인용은 문자 대조를 통과해도 P2R203으로 사람이 확인한다. 현재 OCR 품질 점수 계약이 없으므로 숫자·날짜 인식 정확도를 추정하지 않는다.
