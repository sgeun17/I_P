# phase2_rules_v0.1

작성: 2026-10-02. 상태: 판단팀 구현 초안, 팀 승인 전.
적용 계약: phase2-input-0.2 / phase2-output-0.2 / phase2-errors-0.1.
이 문서는 구현 가능한 공통 경계를 고정한다. 기준팀의 문항별 evidence_rule과 합의된 조직 기준을 대체하지 않는다.

## 판정 대상과 결과

- 입력 targets 중 judge=true인 통제항목의 체크리스트 문항 전체를 판단한다. 관련성 매핑을 다시 수행하지 않는다.
- MET: 해당 문항의 요구사항을 확인할 직접 근거가 현재 제공된 원문에 있다.
- NOT_MET: 해당 대상·기간에 의무가 있었고, 미수립·미수행·기준 위반을 직접 확인할 근거가 있다.
- UNKNOWN: 근거 부족, 판독 불가, 대상·시점 연결 불명, 동일 범위 상충 또는 실행/검증 실패로 판단할 수 없다.
- 자료 미제출·문서 날짜 없음·LLM 실패를 NOT_MET으로 바꾸지 않는다. 문항 밖의 주기·수량·기한을 새로 만들지 않는다.
- 사건 없음·기한 미도래·미해결 예외는 기준팀의 대응 P2_U 코드를 사용한다. N/A나 자동 MET을 만들지 않는다.
- MET의 reason_codes는 빈 배열이다. NOT_MET/UNKNOWN 코드는 실제 카탈로그에 존재하고 결과와 일치해야 한다. 단순히 접두사가 맞는 새 코드는 허용하지 않는다.

## 근거와 인용

- MET와 NOT_MET은 원문 인용이 하나 이상 필요하다. UNKNOWN에 인용을 붙였다면 동일하게 검증한다.
- 인용의 증적 ID와 version, chunk_id, quote, page를 검증한다. 실제 LLM에 전달한 컨텍스트 밖의 청크는 인용할 수 없다.
- 공백 정규화 이외의 자동 보정은 금지한다. 상세 경계는 citation_normalization_v0.1.md를 따른다.
- 원문에 없는 인용으로 MET을 만들면 E403 및 P2E505를 기록하고 검토로 보낸다. 페이지 누락 E407은 경고다.
- 실제 PDF 한 청크가 여러 페이지를 걸치면 현재 데이터 구조로 확인 가능한 것은 페이지 범위뿐이다. 정확한 문장별 페이지 확인에는 전처리팀의 페이지별 위치 정보가 필요하다.

## Self-check

- 구조·인용 검사를 통과한 MET/NOT_MET은 별도 LLM 호출로 재검토한다. 입력은 문항, 제안 판정, 인용문만이다.
- 인용만으로 결과·이유가 성립하는지, 문항 밖 조건을 추가했는지, 미제출을 미이행으로 바꿨는지 확인한다.
- SUPPORTED 외 결과, unsupported_conditions 존재, 호출/형식 실패, 재검토 생략은 UNKNOWN 및 Human Review로 전환한다.
- 재검토 confidence가 0.7 미만이면 UNKNOWN 및 검토로 전환한다. 0.7은 본 구현의 조정 가능한 임시 프로필이며 정확도가 아니다. 0.7 자체는 통과한다.
- 의미 판단은 LLM의 의견이다. 같은 모델을 두 번 사용해도 정확성이 증명되지는 않는다. 실제 문서·정답 라벨로 별도 측정해야 한다.

## 날짜·증적 형식

- 원문 청크에서 완전한 연·월·일 후보와 위치, 출처를 추출한다. 파일명·파일 수정일·업로드일은 작성일로 사용하지 않는다.
- 날짜의 작성/수행/시행/기한/만료 구분은 인접 표지어 기반 후보다. 표 구조나 문맥상 의미가 확정됐다는 뜻은 아니다.
- 최신성 검사는 항목별 max_age_months, date_label, 실행 기준일 as_of가 명시된 때만 수행한다. 전역 기본 개월 수는 없다.
- 기준일에서 달력 기준 개월 수를 뺀 날짜를 하한으로 한다. 월말은 해당 달의 마지막 날로 맞추며 하한 날짜와 기준일을 포함한다.
- 날짜 없음·잘못된 날짜·복수 날짜·미래 날짜·OCR 날짜·기준 누락은 확인 불가다. 오래된 날짜 역시 자동 결함 판정 대신 UNKNOWN/검토로 남긴다.
- 형식 검사는 파서 file_type과 명시적으로 주어진 allowed_types를 대조한다. PDF라는 사실만으로 승인서·정책서·이행기록의 내용 요건이 입증되지 않는다.
- 기준팀의 실제 최신성/인정 형식 목록은 미수신이다. 설정 예제는 합성 시험용이며 업무 기준으로 사용하지 않는다.

## 종합 결과·검토

- critical은 LLM이 정하지 않는다. 현재 공식 임시 정책인 check_kind=[procedure, implementation]을 사용하고 출력에 정책과 rule_version을 남긴다.
- explicit 모드에서 값이 미정이면 중단하고 검토한다. 임의로 true/false를 채우지 않는다.
- critical NOT_MET → 미충족; 그 외 critical UNKNOWN → 확인 필요; 비critical NOT_MET/UNKNOWN → 충족(보완 권고); 모두 MET → 충족.
- 실행 실패 문항만 UNKNOWN으로 바꾸며 나머지 문항을 계속 처리한다. 오류 원문과 재시도 기록은 audit에 보존한다.
- 오류→검토 코드는 공식 phase2_errors.py를 사용한다. OCR 인용은 원본 청크 source로 찾아 P2R203을 부여한다.
- 새 검토 신호(Self-check 확신도, 날짜 등)는 공식 P2R enum에 임의로 추가하지 않는다. human_review.required=true와 audit.review_signals를 함께 전달한다. UI에 상세 사유를 노출할 공식 코드 확장은 인터페이스팀 합의가 필요하다.
- 판정 대상/질문지 없음은 output=null, 처리 상태와 P2E001/P2E002를 audit에 남긴다. items=[]인 공식 출력은 생성하지 않는다.
- 상태는 기존 계약의 VALIDATING → COMPLETED/REVIEW_REQUIRED/FAILED를 따른다. ANALYZING을 추가하지 않는다.

## 재현과 승인

audit는 규칙/스키마 파일 SHA-256, 입력/체크리스트/사유 카탈로그의 정규 JSON SHA-256, 모델, 기준일, 정책, 원응답, 검증 결과를 기록한다. 정규 JSON 해시는 파일 바이트 해시와 다르므로 이름으로 구분한다. KB 정체성은 검색팀 kb_identity.py의 sha256-crlf-v1 규칙을 그대로 사용하며 줄바꿈 차이로 불일치를 만들지 않는다.
미승인 자료는 --allow-draft를 명시한 개발 검증만 허용한다. 정책 변경 시 규칙/검토 프로필을 갱신하고 결과를 섞어 평가하지 않는다.
